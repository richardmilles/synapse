# Checklist : transformer Claude en système de travail

## Processus de départ

- [ ] La tâche choisie revient réellement
- [ ] Le résultat attendu est défini
- [ ] Les informations d'entrée sont connues
- [ ] Les étapes suivent un ordre clair
- [ ] Les critères de qualité sont explicites
- [ ] Les erreurs fréquentes sont documentées

## Skill

- [ ] La Skill couvre un seul processus identifiable
- [ ] Son déclenchement est clairement décrit
- [ ] Les entrées nécessaires sont listées
- [ ] La méthode est testée sur un cas simple
- [ ] La méthode est testée sur un cas ambigu
- [ ] La méthode est testée sur un cas différent de l'exemple

## Automatisation

- [ ] La fréquence apporte une utilité réelle
- [ ] Les sources sont accessibles et identifiées
- [ ] Les critères de sélection sont explicites
- [ ] Le format de sortie est stable
- [ ] Les actions sensibles exigent une validation

## Artifact

- [ ] L'action principale est compréhensible
- [ ] La première version se concentre sur une fonction utile
- [ ] L'outil est testé avec de vraies données
- [ ] Une autre personne peut l'utiliser sans explication

## Plugin

- [ ] La fonction couverte correspond à un besoin réel
- [ ] Les capacités incluses sont comprises
- [ ] Les autorisations sont proportionnées
- [ ] Les méthodes génériques sont adaptées à l'activité

## Claude dans Chrome

- [ ] Le workflow est stable et reproductible
- [ ] Les décisions variables sont expliquées
- [ ] Le niveau de contrôle correspond au risque
- [ ] Les envois, suppressions, paiements et publications restent validés

## Validation finale

- [ ] Chaque fonction résout un problème concret
- [ ] Le système produit moins de travail manuel
- [ ] Les résultats restent contrôlables
- [ ] Une seule nouvelle capacité est ajoutée à la fois
